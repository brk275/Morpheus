# Native audio attachment playback

Conversation and thread audio messages have an inline Play/Pause, Stop and Save card. Nothing is downloaded, decoded or played before an explicit Play action. There is no autoplay preference for audio. Save retains the existing account-scoped transfer path and its larger download limit.

The native-calls package build enables output-only playback; builds without that feature show an unavailable state and retain Save. Playback uses the system default output endpoint without changing the default, call route, OS volume or microphone settings. It never opens a microphone. A supported native 48 kHz output configuration (mono/stereo F32, I16 or U16) is required. Input mono/stereo is linearly resampled from its decoded rate to 48 kHz; stereo is averaged for mono output and mono is duplicated for stereo. Samples are clamped with a fixed 0.8 headroom multiplier. This does not claim high quality sample-rate conversion or exact acoustic presentation time.

## Formats and bounds

- Real Matrix audio events with an admitted audio/mpeg, audio/mp3, audio/wav, audio/x-wav, audio/wave or audio/vnd.wave MIME type only. Filenames and UI hints do not authorize a download.
- WAV: RIFF little-endian PCM 8/16/24/32-bit or IEEE float32; one/two channels, 8–96 kHz. Other WAVE encodings, WAVEFORMATEXTENSIBLE, RIFX and RF64 are unsupported. Chunk offsets, padding, block alignment, byte rate, duplicate fmt/data and exact RIFF size are checked before sample allocation. Unknown bounded chunks are skipped, not parsed as metadata or artwork. Non-finite floating samples are refused.
- MP3: exact symphonia-bundle-mp3/core 0.6.1 with only the MP3 feature. A checked ID3 envelope can be skipped; its tag payload is never interpreted. The upstream MpaReader handles MPEG frames and fixed-size Xing/Info/VBRI duration headers through a capped, revocable memory source. No generic format probe, tag payload, artwork or RIFF reader is linked. Advertised duration never sizes an allocation. Unsupported frame encodings and changes of sample rate/channel shape are refused. Upstream MPEG EOF handling may discard an incomplete final frame; this is playback of decoded frames, not byte-complete file validation. Gapless delay/padding handling uses the upstream bounded frame trimming. MP1/MP2, Ogg/Opus/Vorbis, AAC/M4A, FLAC and video are unsupported; Save remains available.
- Maximum 16 MiB encoded input, 48 MiB retained decoded interleaved f32 samples, three minutes, 100,000 MP3 packets, 4096 decoded frames per packet, 16 KiB encoded packet, 512 RIFF chunks and a cooperative 30-second decoding deadline. The lowest applicable limit wins. Encoded/decrypted input, the fixed decoder buffers and transient vector growth are additional memory; 48 MiB is not a total-process/RSS bound. Duration stays unknown while loading and is calculated only from fully decoded frames, not advertised metadata.

## Privacy, ownership and calls

The existing encrypted-preview preference is unchanged and defaults off. The core requires known room encryption and checks room, original event and encrypted-source signals. A change to this preference synchronously cancels audio before applying it. Decryption happens on the one dedicated owner worker. No SDK media cache, plaintext file, temporary media file, external player or WebView is used. This is memory ownership, not a promise to erase allocator/OS audio buffers securely.

Each Play captures the original account selection, room/view generation, navigation and security generation, plus the existing call request/reservation generation and original RTC output epoch. The download is rechecked before each delegated poll, and playback rechecks lock-free authority per output frame. Account/view/thread/page/logout/close and protected entries retire playback; completed calls or security operations never revive an old intent. A request already handed to HTTP or samples already handed to the OS cannot be recalled. No later delegated poll or output frame can proceed after an observed revocation.

Only one audio download/decode/output worker is admitted process-wide. Stop makes subsequent callback buffers silent. The permit stays with the worker through actual stream destruction, including a slow or stuck native open/drop; a replacement cannot create an accumulating opener pool. A call holds its existing reservation, revokes the prior audio lease, and waits at most three seconds for the actual attachment worker to release before entering SDK join/native media setup. An unreleased worker produces a setup failure rather than overlapping call audio. Incoming ringtone admission, offer policy and microphone/mixer/route ownership are unchanged. The existing RTC output owner is shared with attachment PCM: an admitted ringtone reservation advances its output epoch before a dedicated owner thread waits up to three seconds for the previous actual stream teardown. No UI/event-loop thread waits. Failure keeps the visual offer and reports sound unavailable; it does not start a second stream. A completed or failed ringtone never revives an old attachment intent.

The displayed position counts source frames consumed by the output callback. Pausing does not advance it. It is not a timer or a claim about device latency. Stop drops the decoded clip with its owner; Play after completion starts a fresh explicit load. Idle playback is capped by its ten-minute owner deadline, including pauses.

## Provenance and verification status

The only added registry packages are symphonia-core and symphonia-bundle-mp3 0.6.1, MPL-2.0, upstream ee35874b571a35a9a6e15d3bc9a3aaf8f11fbeee. Their exact crates.io checksums are in Cargo.lock. Existing dependency versions/checksums are preserved; no build script, proc macro, SIMD/rustfft, metadata/tag/artwork crate or external binary is added. Full MPL and source notices are in licenses/Symphonia-MPL-2.0.txt and licenses/Symphonia-NOTICE.txt, included as package resources and referenced in About.

This is an unexecuted source proposal. Synthetic unit source covers RIFF bounds/sample conversion, MP3 decode and invalid inputs, per-poll security ABA, original call-request authority, callback resampling/position, pause and irrevocable cancellation. Actual current native builds, these tests, generated UI/keyboard/geometry, malformed input resource behavior, supported output devices and installed playback remain independent hosted/runtime gates. Existing acceptance budgets and workflow selections are unchanged.
