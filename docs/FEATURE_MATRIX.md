# Feature and release matrix

This is the beta gate, not a claim that the features are already implemented.
Use the [Cinny comparison checklist](CINNY_BENCHMARK.md) for the detailed
chat-behavior benchmark.
Mark an item complete only after it works on macOS, Linux, and Windows where
platform behavior is relevant.

| Area | Beta requirement | Status |
| --- | --- | --- |
| Accounts | Multiple isolated sessions, bottom-left switcher, safe logout | Wired; two-server isolation, switch, and restart core test passed. An isolated macOS app added Alice and Carol on separate loopback homeservers, switched between their distinct room lists, and logged out both accounts. Inactive account send queues pause with sync; an already in-flight request may finish. Selected-account room queues retry recoverable send errors with bounded backoff. A live call blocked account switching until Leave; other-platform UI checks remain |
| Authentication | Password and browser-based SSO/OIDC, session restore | Password and session restore tested locally; legacy SSO and delegated OAuth/OIDC with SDK PKCE, native registration, system-browser loopback, and vaulted refresh tokens are implemented. New hosted protocol tests and real provider/browser acceptance remain pending |
| Encryption | Verification, encrypted media, key backup and recovery | Two-device encrypted message, restart, new-device backup recovery, and encrypted file roundtrip passed in local tests. Native Settings shows active-account security status, creates a one-time recovery key, and accepts an existing key or passphrase; account changes and normal close are guarded while that key must be saved. A fresh macOS profile imported a key and displayed two historical encrypted events, including before/after pagination. A second genuinely new signed app imported its account's protected recovery key and reached Device Verified, Recovery Enabled, and Key backup Enabled. A fresh unverified second app then completed own-device SAS with the verified app: both displayed matching emoji and numbers, each comparison was explicitly confirmed, and the new device reached Verified. A completed-flow status poll briefly showed an error before manual Refresh displayed Verified; the UI now checks durable device trust when a finished request is pruned, with a focused test passing. The revised completion screen still needs live retest. Other-platform and failed-recovery acceptance remain open |
| Navigation | DMs, Spaces, multi-parent rooms, discovery, invites | Space graph and rail wired; private room/Space creation, room ID/alias join, and invitation accept/decline UI wired; local core workflow passed. Newly created private rooms now include Megolm state in their initial create request; four rooms and a new DM had server-confirmed encryption in a fresh local test. Existing cleartext rooms and Spaces are not converted. Public directory search, result Join, and routed `matrix.to` alias Join passed an isolated macOS app click-through on loopback Synapse; federation, other platforms, and full navigation QA remain open |
| Messaging | Rich composer, replies, edits, reactions, threads, media, drafts | Plain-text reply/edit/heart reaction and a text thread panel wired; encrypted live action test passed. Encrypted per-room drafts passed two-account restart/isolation and plaintext-scan checks; a send completing after app exit can leave a stale draft. Bounded encrypted attachment upload/download core passed a local Alice-to-Bob roundtrip; native attach/save dialogs, progress, cancel/retry, and attachment card are wired but need live UI QA. An opt-in Markdown room composer and account-bound formatted reply/edit sends are wired; strict HTML serialization tests passed 4/4, a native Md toggle/encrypted-send click-through passed on macOS, and a fresh encrypted Synapse main/reply/edit roundtrip passed with cross-account rejection. Safe native rich text is now wired in timeline and thread views for a bounded HTML subset; Bob's decrypted message and edit reached that projection in a fresh local test. Unsupported markup falls back to literal plain text. A fresh account-free macOS preview showed bold text in both timeline and thread root with matching plain accessibility labels; focused app tests passed before the latest outgoing-capture changes. Encrypted per-thread drafts are now wired with account/room/root isolation, guarded restore, exact send-acknowledgement tracking and revision protection; new hosted regressions and live UI acceptance remain pending. Pending-request reconciliation after restart and retry/cancel controls remain open. Live encrypted rendered-text UI acceptance, mention suggestions, sticker composition, media previews, and full UI QA remain open. A macOS native preview loaded 10,000 mixed-height rows, exposed only 5–7 accessibility rows per view, and reached message #10000; a real 10,000-message Matrix room and other platforms remain untested |
| Search | Message and room search | Account-scoped encrypted local message index returns sender, body, room, time, and event context; room and cross-room queries, exact-term matching, event-focused context, cross-account isolation, restart persistence, and a plaintext-store scan passed with native sliding and forced classic sync. Public room directory search passed a two-Synapse core test and macOS UI click-through. The native current-room search panel, result list, and selected-event context passed an isolated macOS click-through with a newly sent message; all-room UI, large-history behavior, and other platforms remain open |
| Administration | Room creation, roles/power levels, bans, redactions, settings | Private room/Space creation UI and account-scoped member administration are wired. A loopback core test passed rename/topic, default permission denial, power promotion/demotion, redaction, kick/reinvite, ban/blocked join, and unban/rejoin, including account-bound rename/topic/redaction rejection after an account mismatch. A macOS Slint click-through on a disposable room confirmed Invite, exact power 50, Kick, Ban, and Unban on the homeserver, with confirmation dialogs; manual roster Refresh was needed to display each changed state before the subsequent settle-and-refresh fix. A second fresh-profile macOS click-through saved room name/topic and redacted a message through a keyboard-accessible confirmation; direct Synapse reads verified the state and redaction. Permission-error UI, the roster-refresh fix, full administration breadth, and other-platform QA remain open |
| Notifications | Active-account native notifications while process runs | Matrix push-rule handler and native presenter wired with active-account, visible-room, own-send, duplicate, age, preview, and sound policy. Policy tests passed locally. A signed macOS QA app delivered an active-account alternate-room notification under the exact Morpheus bundle ID; visible-room, inactive-account, and post-quit messages produced no request. A banner screenshot, preview text, sound, Linux, and Windows runtime acceptance remain open. See [notification behavior](NOTIFICATIONS.md) |
| Configuration | In-app editor, TOML, live reload, themes, shortcuts | Theme, font scale, density, pane size, unread-first, and notification settings are wired; next-call microphone/speaker ID selectors now share the validated TOML preferences (hosted and hardware acceptance pending for this batch); config saves replace atomically across platforms. In-app notification saves update the presenter immediately, and a malformed theme retains the last valid appearance while still applying valid notification privacy changes. Highlight phrases are normalized and bounded. Four shortcuts (`quick_switcher`, `search`, `next_unread`, `previous_unread`) now share an in-app editor and validated live TOML settings; the room picker and unread navigation use the current Home/Space, and text editing/modal keys keep precedence. Parser, dispatcher, picker, and invalid-save regressions passed on all four native targets at `95f61da`; actual keyboard and broader malformed-edit acceptance remain open |
| Calls | Encrypted DM and room voice/video with Element Call interop | An explicit account/room Element Call Matrix 2.0 (`Sticky2025`) choice is implemented alongside Standard and Legacy, with unchanged default and no automatic fallback. Its native compilation and targeted tests passed on all four platforms at `16fbd5b`; UI and production interoperability acceptance remain pending. Experimental native room audio with group mixer wired behind `native-calls`; macOS loopback two-device encrypted audio, decoded `Camera` and `ScreenShare` I420 transport, roster, and leave/rejoin passed with the lowercase `m.call#room` default. An opt-in legacy `RoomState` call passed encrypted microphone/video and departure with an Element Call v0.26.1 browser peer. A fresh stock `matrix_2_0`/`Sticky2025` attempt failed camera subscription: Element Call decrypted and could calculate two memberships, but its live roster stayed empty after sticky updates fired while the events were still encrypted. An explicit browser session refresh proved media transport only; current-format stock interop remains open. A live macOS cleartext-room call showed both participants but no remote camera: Bob published frames and advertised `Camera` locally, while Alice received no stream or track. The pinned current-format RTC transport cannot map a cleartext membership to an authenticated sender device, so current-format calls now reject unencrypted rooms before opening or joining. Opening a slot now checks MatrixRTC service discovery before writing room state. A fresh encrypted two-device test observed leave-triggered media-key index 1 on Alice and Bob decoded newly published camera frames after rejoining. A separate forced signalling-socket close produced degraded and recovered connection events without a membership change; Bob decoded new encrypted camera frames afterward. A full network outage and SFU restart remain untested. A fresh encrypted macOS GUI call joined and displayed two participants; its outgoing capture controls and source picker are wired, and the display-share UI reached Active. Bob's separate observer device saw Alice reachable; a later fresh signed GUI call delivered 10 nonblank encrypted `ScreenShare` I420 frames. Camera publication from the GUI and a live received frame in Morpheus's call stage remain unverified. On the tested FaceTime camera, the first GUI open failed format negotiation. After a format-selection change, a second GUI attempt stayed Starting for about 20 seconds, produced no frame, and moved through Stopping and Failed to Off; native camera capture remains blocked on that macOS device. Mute/deafen controls have applied-state feedback, and persisted microphone/speaker selectors now use host-qualified CPAL IDs with explicit unavailable-device errors and next-join application only. This audio-selection batch still needs hosted native compilation and real routing/permissions/unplug acceptance; DM ringing and Linux/Windows runtime checks remain |
| Voice spaces | Drop-in room calls and visible participant roster | Shared state marker write/read passed between local devices, using an explicit server read because sliding sync omits this custom event; joined-call roster UI passed an isolated macOS two-participant click-through. Voice-space navigation and per-account local designation controls are wired, and selecting a marked room now enters its call stage and attempts a join. End-to-end drop-in acceptance and other-platform UI checks remain pending |
| Screen share | Window/display picture plus microphone audio | Native macOS display and window pixels each reached Bob through an encrypted 640×360 MatrixRTC screen track in separate command-line loopback tests; audio also passed. The joined-call display/window picker and Start/Stop share controls are wired. Fresh encrypted macOS GUI calls selected a display and showed an active local share; Bob's separate observer device decoded 10 nonblank `ScreenShare` I420 frames in the second run. Bob-side unpublish after Stop and a received frame in Morpheus's call-stage tile remain unverified. Packaged-app permissions, window-share GUI behavior, Element Call interoperability, and Linux/Windows capture remain open |
| Accessibility | Keyboard and VoiceOver/Narrator/Orca checks | Main macOS offline-preview keyboard path, menu autofocus, forward modal Tab loops, and Escape focus return checked; physical Shift+Tab, screen-reader, and other-platform checks pending |
| Distribution | Signed, installable, updateable packages | Public source remains pre-alpha. Platform-selected unsigned package validation is wired, with installer uploads disabled. Historical private QA built all four platform variants across earlier revisions; those artifacts are withdrawn before public development. Historical publication revision `bc1614b` passed all four native targets (run `38092977119`); that evidence does not verify later native changes or packaging. See the verification log for current candidate results. Settings now exposes explicit signed-update Check/Download/Discard/Restart controls with call/recovery exclusion and orderly worker shutdown; controls remain disabled without a compiled feed/key and a supported AppImage installation. Its controller and security regressions passed on all four native targets at `95f61da`. Installed-package QA, signing, notarization, an updater feed, and update/uninstall acceptance remain open |

Computer-audio sharing, mobile clients, executable plugins, and a Morpheus
hosted call service are later work.
